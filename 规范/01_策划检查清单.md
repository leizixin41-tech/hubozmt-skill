# 01 · 策划检查清单(规范 v2)

> 你是策划设计师。你交出去的东西决定成片是不是「看得见产品在干活」。
> 本文件是 `roles/planner.md` 的补充:那里讲怎么分段、怎么设计;这里讲 **v2 必须交什么、按什么标准、怎么自查**。
> 样张:`episodes/_示例_规范v2_scrapling/`(段表、截图、截图 .json 都可以直接照抄格式)。

## 一、你要交的三样
| 交接物 | 内容 | 谁读 |
|---|---|---|
| `02_段表.json` | 每段的口播、逻辑、主视觉、素材、交互、文字、景深(机器读,门禁查它) | `hz plan` / 合成师 |

## 二、段表格式
模板:`规范/模板_02_段表.json`。每段 11 个字段,**缺一个门禁就不过**:

| 字段 | 写什么 | 例子 |
|---|---|---|
| `id` | 段号,从 1 起 | `4` |
| `t0` `t1` | 起止秒数,**取自 `work/words.json`**,不要估;段与段首尾相接 | `6.26` `9.7` |
| `kind` | `hook` 开场钩子 / `case` 案例(展示产品)/ `bridge` 过渡 / `end` 收尾 | `case` |
| `vo` | 这段口播原文 | `现在 GitHub 上已经飙到了 90K 的 Stars` |
| `logic` | **这段要让观众看懂什么逻辑**(一句话,讲道理,不是讲画面) | `热度是真的:仓库页上的星标数` |
| `ui_shot` | 主视觉是什么、在哪一层、占多大 | `GitHub 仓库页大图(中景,占画面 1/4 以上),框住 Star 按钮` |
| `assets` | 本段用的素材(下表) | `[{"file":"shots/gh_repo.png","role":"screenshot","boxes":["star"]}]` |
| `interactions` | 本段的交互动画(下表):**用什么 UI 动画证明上面的逻辑** | `[{"kind":"frame","at":8.5,"target":"shots/gh_repo.png#star","label":"★ 90.3k","sfx":"pop"}]` |
| `text_role` | 屏幕上的每一条字:内容、角色、挂在哪一层 | `[{"text":"90,271","role":"title","layer":"front"}]` |
| `depth_plan` | 每层放什么 + 焦点在哪层 | `{"front":["数字"],"mid":["仓库页截图"],"focus":"mid"}` |

### `assets` 每一项
| 字段 | 说明 |
|---|---|
| `file` | 相对 `assets/` 的路径,如 `shots/gh_repo.png`;文件必须存在 |
| `role` | `screenshot` 截图 / `crop` 局部截图 / `record` 录屏帧(这三种算「真实素材」)/ `logo` / `icon` / `copy` 文字素材 / `gen` 生图 |
| `boxes` | 要框选的区域名(必须在截图同名 `.json` 的 `boxes` 里) |
| `source` | 来源网址。用 `hz capture` 截的图会自动写进同名 `.json`,这里可以不写 |
| `text` | 只给 `copy` 用:终端命令、代码、HTML 片段的**原文**(必须同时写 `source`) |

### `interactions` 每一项
| 字段 | 说明 |
|---|---|
| `kind` | 只能是动画库存里的种类:`frame` 框选 · `pulse` 脉冲 · `count` 数字跳动 · `terminal` 终端 · `load` 浏览器加载 · `swap` 前后对比 · `pills` 逐项点亮 · `click` 鼠标点击 · `code` 代码逐字 · `hl` 行高亮 · `list` 列表 · `results` 结果行 · `progress` 进度条 · `input` 输入框 |
| `at` | 动作发生的秒数,对准口播关键词的读音时刻;必须落在本段里(允许提前 0.2 秒) |
| `target` | 作用在哪:截图区域写 `文件#区域名`(门禁会核对区域存在),其他写清楚是哪个元素 |
| `label` | 框选的呼出标签(可选,规则见下面「文字」) |
| `sfx` | 配什么音效:`tick` `pop` `chime` `swish` `whoosh` `thump` `keytap` `shimmer`,不配写 `none` |
| `taps` | 只给 `keytap`:敲几下(默认 8) |

### `text_role` 每一项
`role`:`title` 主标题 / `sub` 副句 / `label` 标签 / `note` 注释;`layer`:`front` / `mid` / `back`。

## 三、写段表的步骤
1. **按语义切段**:读 `work/transcript.md` 和 `work/words.json`;一段 = 一个要证明的点,1–5 秒。
2. **定段类型**:一期里通常只有第 1 段是 `hook`(纯字 ≤3 秒),最后一段 `end`;其余讲产品的都是 `case`。案例段总时长要 ≥ 人声的 50%。
3. **逐句映射**:对每一段先写 `logic`(观众该看懂什么),再问自己「哪个画面能**证明**它」,写进 `ui_shot` 和 `interactions`。证明不了的话(比如纯形容词「非常好用」),就和相邻的案例段合并,或者用收尾画面承接。
4. **配方**:先查下面的「产品段配方」,有现成的就照用。
5. **列素材**:配方需要什么截图,就去截(第五节),把区域名写进 `boxes`。
6. **写文字**:文字只做标注,见第六节。
7. **写景深**:见第七节。
8. **跑门禁**:`bin/hz plan <本期>`,按报错改到通过。

## 四、产品段配方
| 口播在说 | 主视觉(中景) | 交互动画 | 文字 |
|---|---|---|---|
| 「这个项目叫…」「记住这个项目」 | GitHub 仓库页上半部截图 | `frame` 框住仓库名(标签写 `作者 / 仓库名`) | 一条主标题 |
| 「XX K Stars」「很火」 | 仓库页截图,星标按钮清楚可见 | `count` 数字跳到 API 实数 + `frame` 框住 Star 按钮(标签抄页面上的数,如 `★ 90.3k`) | 数字 + 一行小字 |
| 「一行命令就能装」 | PyPI / npm / README 安装段截图 | `frame` 框住安装命令 + `terminal` 前景终端逐字敲同一条命令,输出成功行 | 一条主标题 |
| 「打开网页 / 动态加载 / 爬下来」 | 浏览器假窗,内容 = 目标网页真实截图 | `load` 地址栏打字 → 转圈 → 内容出现 + `frame` 框住抓到的那块 | 主标题 + 一个技术名纸片 |
| 「网站改版也能识别 / 自适应」 | 官方文档截图 | `swap` 改版前 / 改版后 HTML 闪切(HTML 抄官方文档)+ `code` 官方示例代码逐字 + `hl` 高亮关键参数 + `frame` 框住命中的那行 | 主标题 |
| 「能绕过反爬 / 支持 A、B、C」 | README 能力清单截图(暗场里) | `frame` 依次框 2 条 + `pills` 能力名逐项点亮打勾 | 主标题 |
| 「结果是…」「输出 JSON / 表格」 | 结果的 JSON / 表格(真实输出,或官方文档示例) | `results` 结果行逐行弹出 / `code` + `frame` 框住关键字段 | 主标题 |
| 「点一下就…」 | 产品界面截图或用户录屏 | `click` 鼠标沿路径点击 + 点后的状态变化(`swap` / `load`) | 标签 |
| 收尾「拿来就能用」 | 仓库名片条(仓库页顶部一条) | `pulse` 星标脉冲 | 主标题 + 仓库地址 |

## 五、素材包(出片前置条件)
**缺一样就先补,不许拿灰色占位块、空白窗口顶。**

| 素材 | 要求 | 怎么拿 |
|---|---|---|
| 项目 logo | 透明底或干净底,来源可查 | 仓库 raw 链接下载 → `assets/logo/` |
| GitHub 仓库页截图 | 2 倍清晰度;量出仓库名、Star、Fork 的位置 | 下面「截图命令」 |
| 产品页 / 文档页截图 | 关掉 Cookie 弹窗、登录条 | `--hide` |
| 关键区域局部截图 | README 某一节、某个功能列表 | `--el <选择器>` 只截这块 |
| 终端命令原文 | 一字不差,抄官方 README / PyPI | 段表里 `role: "copy"` + `source` |
| 代码 / HTML 片段 | 抄官方文档,不自己编 | 同上 |
| 框选坐标 | 每个要框的区域都在截图 `.json` 的 `boxes` 里 | `--box 名字=选择器` |
| 数字 | 以官方 API / 页面为准,写清查询日期 | 例:`api.github.com/repos/作者/仓库` 的 `stargazers_count` |

### 截图命令
```bash
(以下都是样张实际跑过的命令)
# GitHub 仓库页:2 倍清晰度,量出仓库名 / Star / Fork / 提交数的位置
#(仓库名不要写 @Scrapling:页面上到处是这个词,会框错;用 CSS 选择器)
bin/hz capture url https://github.com/D4Vinci/Scrapling <本期>/assets/shots/gh_repo.png --size 1440x900 --scale 2 --wait 6 \
  --theme light --box title="div.f3 strong" --box star=@Star^ --box fork=@Fork^ --box commits=@Commits^

# 文档页:隐藏 Cookie 弹窗,量出标题和第一段
bin/hz capture url https://scrapling.readthedocs.io/en/latest/parsing/adaptive.html <本期>/assets/shots/docs_adaptive.png \
  --size 1280x800 --scale 2 --wait 5 --theme light --hide ".md-consent" --hide "[data-md-component=consent]" \
  --box h1=h1 --box intro="@Adaptive scraping (previously"

# PyPI 页:量出安装命令
bin/hz capture url https://pypi.org/project/scrapling/ <本期>/assets/shots/pypi.png --size 1280x800 --scale 2 --wait 5 --box pip=#pip-command

# 只截 README 里的一块(局部图):样张里截 Scrapling README 的反爬能力清单就是这样截的
bin/hz capture url https://github.com/D4Vinci/Scrapling <本期>/assets/shots/gh_fetching.png --size 1440x900 --scale 2 \
  --theme light --el "@Anti-bot Bypass^^" --pad 16 --box tls="@Can impersonate browsers" --box antibot="@Anti-bot Bypass^"
```
选择器写法:CSS 选择器;或 `@文字`(找包含这段文字的最小元素);末尾 `^` = 取它所在的按钮/链接/列表项整体,`^^` 再往外一层。
截完会打印每个区域的结果;`boxes_missing`(没找到)和 `boxes_outside`(在截图范围外)要处理掉。**截完亲眼看一遍**:区域框得对不对、有没有弹窗挡住、有没有真实个人信息。

### 手工截图(要登录、被反爬拦、需要真实操作过程时)
放 `assets/shots/`,并手写同名 `.json`:
```json
{"source": "https://…(截图的网址;用户提供的写 用户提供)", "size": [2880, 1800], "boxes": {"star": [0.843, 0.209, 0.079, 0.031]}}
```
`boxes` 是 0–1 的比例 `[左, 上, 宽, 高]`,相对整张图。

### 目录
```
assets/shots/  截图、局部截图(*.png + 同名 *.json)
assets/rec/    用户给的录屏 / 录屏抽帧
assets/logo/   logo、图标
```
截图、logo 都要登记进素材库:`bin/hz asset add …`(见 `roles/planner.md`)。

## 六、文字只做标注
- 案例段:**主标题最多 1 条,文字最多 4 条,每条最多 16 个字**。长句交给画面,不上屏。
- 框选标签:**中文 ≤8 字、英文 ≤14 个字母**;写**事实**(页面上能看到的东西:`★ 90.3k`、`官方安装命令`、`D4Vinci / Scrapling`),不写形容词(不写「超强」「秒杀」)。
- 数字以官方数据为准:计数动画跳到 API 实数,标签抄页面显示的数;口播说的是约数(90K)也没关系,**画面不编造**。
- 每条字写明挂在哪一层:标题一般在 `front`;截图上的标签跟着截图在 `mid`;远处的淡字在 `back`。

## 七、景深(depth_plan)
| 层 | 放什么 | 例 |
|---|---|---|
| `front` 前景 | 可交互的控件(终端、代码块、浏览器窗、pills)、本段标题 | 终端敲命令 |
| `mid` 中景 | 截图窗(主视觉) | 仓库页截图 + 框选 |
| `back` 背景 | 弱化的 UI、上一个话题的截图、巨大淡字 | 虚掉的文档截图 |

每段至少用两层;`focus` 写焦点落在哪层(观众该先看哪)。**不许所有东西堆在同一个深度。**

## 八、交接前自查(逐条打勾)
- [ ] `brief.json` 有 `"spec": 2`;产品介绍类 `gen_limit` 为 0
- [ ] 段落首尾相接,盖满整条人声;时间都取自 `words.json`
- [ ] 每段都写了 `vo` 和 `logic`;每个案例段的 `interactions` 能**证明**它的 `logic`
- [ ] 每个案例段至少 1 张真实截图;全片不同截图 ≥3 张
- [ ] 每个案例段至少 1 个交互,超过 3.5 秒至少 2 个;交互时刻对准关键词读音
- [ ] 所有 `文件#区域名` 都在截图 `.json` 的 `boxes` 里;截图亲眼看过,无弹窗、无个人信息
- [ ] 终端命令、代码、HTML 都是官方原文,写了 `source`
- [ ] 数字查过官方数据,写了查询日期(在 `02_方案.md`)
- [ ] 案例段文字 ≤4 条、主标题 ≤1 条、每条 ≤16 字;标签写事实
- [ ] 每段 `depth_plan` 用了两层以上,写了 `focus`
- [ ] 纯文字段只有开场钩子,≤3 秒
- [ ] `bin/hz plan <本期>` 通过;`bin/hz plan <本期> --sfx` 生成了 `03_sfx.json`

## 九、门禁常见报错
| 报错 | 怎么改 |
|---|---|
| `这些词没有映射到任何一段` | 段落之间有空隙,或最后一段结束太早;按 `words.json` 调 `t0/t1` |
| `案例段没有真实截图/录屏帧` | 去截图;生图、logo、文字素材都不算 |
| `案例段 X 秒只有 1 个交互动画,至少 2 个` | 加一个框选 / 脉冲 / 计数,或把段拆短 |
| `交互目标 xx.png#star 找不到` | 重截并加 `--box star=…`;或手写进 `.json` 的 `boxes` |
| `素材 xx.png 没有来源` | 用 `hz capture` 重截,或在段表里写 `source` |
| `纯文字段 X 秒,最长 3 秒` | 拆段,或给这段加截图和交互 |
| `景深只用了 1 层` | 把标题放 front、截图放 mid |
