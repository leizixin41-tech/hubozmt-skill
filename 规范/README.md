# 规范 v2 · 口播动效片「案例段必须看得见产品在干活」

> 2026-10-29 起的新期都按这套规范做。目标:**口播动效片不能以纯文字为主;案例段必须有看得懂的 UI 交互动画和真实素材。**
> 起因:Scrapling v1–v5 一直是「大标题 + 副句」撑画面,截图小到看不清、假 DOM 是灰色占位块、浏览器只在转圈、暗场露出竖缝(对照见 `03_合格vs不合格.md`)。

## 这套文档怎么用
| 文件 | 给谁 | 内容 |
|---|---|---|
| `01_策划检查清单.md` | 策划设计师 | 段表怎么写、每句口播怎么对画面、截图怎么截、交接前逐条自查 |
| `02_合成师_动画与素材库.md` | 合成师 | 动画库存 `hz.k.*` 的参数表、假窗结构、框选规范、景深约定、暗场、音效挂钩、性能上限、已知坑、版本记录 |
| `03_合格vs不合格.md` | 所有人 | 一页看懂什么样不合格、什么样合格(真实截帧对照) |
| `模板_02_段表.json` | 策划设计师 | 段表模板,复制到本期改 |
| `样张_scrapling/` | 所有人 | 按本规范做的 27.6 秒样张(阅读副本):段表、截图、场景页、音效表、静帧,**照着抄**;能运行的原件在 `episodes/_示例_规范v2_scrapling/` |
| `img/` | — | 对照图(`03` 用) |

## 怎么打开:brief.json 写 `"spec": 2`
```json
{"size": "1920x1080", "fps": 30, "style": "space3d", "gen_limit": 0, "spec": 2}
```
- 写了 `"spec": 2` 的期才会被下面的门禁拦;**没写的旧期一律不受影响**(旧期重渲、重检行为和以前完全一样)。
- 产品/开源项目介绍类视频 `gen_limit` 默认 0:不靠生图撑画面。

## 七条硬规矩
1. **每个镜头的最低构成**:主视觉是 UI 或真实截图/录屏帧 + 至少 1 个交互动画 + 文字只做标注。「整段大标题 + 副句」不合格。
2. **口播→画面映射表**:段表里每一句口播写清「展示什么逻辑(`logic`)+ 用什么 UI 动画证明(`interactions`)」。有一句没映射,不许进渲染。
3. **素材包是出片前置条件**:logo、GitHub/产品页截图、关键区域局部截图、终端命令原文、可框选的坐标(截图同名 `.json` 里的 `boxes`)。缺截图就先截,不许拿占位块顶。
4. **动画库存**:框选扫过、高亮脉冲、计数跳动、终端逐字 + 完成勾、浏览器转圈→出内容、改版前后闪切、列表/pills 逐项点亮、面板滑入、鼠标点击路径……都在公共库 `engine/web/hz_kit.js`,时长、缓动、景深层、勿出画都写在 `02` 里。
5. **景深约定**:前景 = 可交互控件和标题,中景 = 截图窗,背景 = 弱化 UI;文字挂在所属的层上。不许所有东西堆在同一个深度。
6. **转场与底板**:纸底和暗场之间不许出现竖缝;暗场一律用屏幕空间的满幅淡入淡出(`hz.k.dark`);底板只要盖住镜头就够,不铺无限大的板。
7. **验收**:抽帧必须看得出「产品在干活」;案例段纯文字的面积和时长有硬上限(下面「量化」一节,`hz check` 自动量)。

## 三条约束
- **不靠付费生图撑画面**;优先真实截图 + UI 动画。生图只能当氛围,不能是案例段的唯一素材。
- **本机资源有限**(MacBook Air · Apple M5 · 16 GB):小底板、少硬跑全量检查(见下面 Q4)。
- **旧 episode 只作参考**:整理文档以升级规范为主;公共引擎和动画库**只增不改**,避免悄悄改坏已交付的成片(见 Q3)。

## 流程里多了三道门
```
策划:02_段表.json + 02_方案.md + assets/shots/*.png(+同名 .json)
  └─ bin/hz plan <本期>          ← 门 1:段表门禁(映射、素材、交互、文字、景深、覆盖率)
     bin/hz plan <本期> --sfx    ← 按段表生成音效表 03_sfx.json
合成:03_scene.html
  └─ bin/hz check <本期>         ← 门 2:版面检查 + 画面丰富度(UI 占比、连续纯字、交互次数是否真的做了)
     bin/hz web_render <本期> final  ← 门 3:没通过「改完之后的全片检查」就拒绝渲染
```

## 量化标准(阈值都在 `tools/plan.py` 的 `RULE`)
| 项 | 标准 | 谁查 |
|---|---|---|
| 案例段交互次数 | 每段 ≥1;段长超过 3.5 秒 ≥2 | plan(段表写了没)+ check(页面里真做了没) |
| 案例段真实素材 | 每段 ≥1 张真实截图/局部截图/录屏帧(文件在 `assets/`、有来源) | plan |
| 全片真实截图 | 不同的截图 ≥ min(3, 案例段数) 张 | plan |
| 案例段文字 | 主标题 ≤1 条、文字 ≤4 条、每条 ≤16 字 | plan |
| 纯文字段 | 没有素材也没有交互的段 ≤3 秒(一般只有开场钩子) | plan |
| 案例段占比 | 案例段总时长 ≥ 人声时长的 50% | plan |
| 案例段画面构成 | 「看得清的 UI/截图占画面 ≥18%」的帧 ≥70% | check |
| 案例段连续纯字 | ≤1.5 秒 | check |
| 口播覆盖 | 段落首尾相接盖满整条人声(空隙 ≤0.15 秒),每个词都落在某段里 | plan |
| 景深 | 每段至少用两层,写明焦点层 | plan |

## 五个问题的答案

### Q1 交接物是什么?「无 UI 不进渲」怎么强制?
- **交接物 = 三样**:`02_段表.json`(机器读,门禁查它)+ `02_方案.md`(人读:色板、空间路线、每段设计说明)+ `assets/` 里的素材(截图都带同名 `.json`:来源、尺寸、框选区域)。
- **强制靠三道门**(只对 `spec: 2` 的期生效):
  1. `hz plan`:段表缺字段、有口播没映射、案例段没截图/没交互、框选目标在截图里找不到 → 报错,退出码 1。
  2. `hz check`:先跑门 1;再逐帧量 UI/截图占画面的比例、连续纯字时长;再读页面里动画库的记账 `hz.k.log`,核对每个案例段**真的**做了段表要求的交互次数。
  3. `hz web_render final`:门 1 不过,或 `out/check.json` 不是「全片、通过、比 03_scene.html 和段表都新」→ 直接拒绝渲染,提示先跑 `bin/hz check`。

### Q2 截图谁负责?目录怎么放?
- **策划负责,用脚本截**:`bin/hz capture url <网址> <本期>/assets/shots/<名字>.png --scale 2 --box 名字=<选择器> ...`。脚本同时写同名 `.json`(来源、时间、尺寸、框选区域),合成师直接用,不用猜像素。
- **手工截图只在**:要登录、有反爬拦截、需要真实操作过程时。手工截的图同样放 `assets/shots/`,并手写同名 `.json`(至少 `source` 和 `size`;要框选就补 `boxes`,0–1 比例)。
- **合成师不截图**。缺图就退回策划补,不拿占位块顶。
- 目录:
```
<本期>/assets/
  shots/   网页/GitHub/产品页截图、局部截图(*.png + 同名 *.json)
  rec/     用户给的录屏 / 录屏抽帧(来源写用户提供)
  logo/    项目 logo、图标(从仓库 raw 链接拿,登记来源)
```
终端命令、代码、HTML 片段这类「文字素材」不存文件,直接写在段表 `assets` 里(`role: "copy"`,带 `text` 和 `source` 网址)。

### Q3 动画库存是公共库还是每期复制?怎么管版本?
- **公共库**:`engine/web/hz_kit.js`,场景页用相对路径加载,不复制进每期。
- **只增不改**:要改已有函数的行为就起新名字(如 `frame2`),旧函数原样保留,所以已交付的旧期重渲不会变。修 bug 例外,但必须写进 `02` 的「版本记录」,并说明影响哪些期。
- 版本号在 `hz.k.v`(现在 `1.0`),每次加函数加小版本号(1.1、1.2…)。
- 只用一次的效果写在本期的 `03_scene.html` 里;用了两期以上、确定好用,再收进公共库。

### Q4 在 Air 上:底板多大、同时几层动画、能不能跑第二次全量检查?
- **背景不在世界空间铺板**:纸底由 `hz.space` 自带(屏幕空间),暗场用 `hz.k.dark`(屏幕空间)。世界空间里不放任何「为了盖住镜头」的大板。
- **世界空间里的板(卡片、截图窗、色块)最长边 ≤ 4000px**;需要盖住镜头时按「该深度能看到的画面宽度 ≈ 画面宽 ×(镜头距离 − z)/ 1600」算,刚好盖住就停。大于画面的板关掉景深模糊(`dof:false`)——大面积模糊最吃性能。
- **同一时刻可见的图层建议 ≤6 个**,其中带景深模糊的 ≤3 个(样张每段 3–4 个图层,渲染顺畅;这是建议值,不是实测上限)。
- **检查不贵**:27.6 秒的样张全片检查用时约 12 秒(4 个无界面浏览器)。规则:
  - 改某一段时只查这一段:`bin/hz check <本期> --from 13 --to 17`;
  - 交给渲染前**必须**跑一次全片检查(渲染门禁要求);之后没改动就不要再跑;
  - **不要在渲染的同时跑检查**;Air 上渲染建议 `--workers 4`(默认 6)。
- 第二次全量检查**不禁止**,只在「改过之后」才需要;没改动重复跑是浪费。

### Q5 丰富度怎么量化?
见上面「量化标准」。核心三条:**每个案例段至少 1 个交互(超过 3.5 秒至少 2 个)、至少 1 张真实截图、连续纯字不超过 1.5 秒**;纯文字段只允许开场钩子那种 ≤3 秒的。
